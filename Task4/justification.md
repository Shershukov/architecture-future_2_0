Yandex Cloud (ru-central1)
├── VPC Network (3 зоны: a, b, d)
├── Kubernetes Cluster (Managed, 3 ноды)
├── PostgreSQL Cluster (Managed, Vault)
├── Bastion Host (VM, public access)
├── Object Storage (Data Lake)
└── KMS (Шифрование)

|            | Параметры                       | Обоснование                                               |
|------------|---------------------------------|-----------------------------------------------------------|
| K8s        | 2 vCPU, 4 GB, 10 GB SSD, 3 Ноды | Оптимально для микросервисов, Минимум нод для HA-кластера |
| PostgreSQL | 10 Gb                           | Надежный уровень для запуска приложения                   |
| Зоны       | ru-central1-a,b,d               | Отказоустойчивость (3 зоны)                               |
| NAT        | Public: true, Private: false    | Безопасность (изоляция приватных ресурсов)                |
| CIDR       | Public: true, Private: false    | Требование Yandex Cloud, изоляция трафика между зонами    |

Декларативный подход позволяет использовать одну и ту же конфигурацию без необходимости ее повторения с целью получения одного результата для разных окружений. Конфигурация в Git позволяет хранить историю изменений и производить ревью.
Также версионирование позволяет легко вернуться к предыдущей версии.

Infrastructure as Code позволяет использовать одну конфигурацию в разных окружениях: дев, тестовый стенд, прод (Воспроизводимость). Что сокращает время развертывания и восстановления в случае откатов.

Масштабируемость становится гибче за счет возможности конфигурирования количества нод всего одним параметром.
